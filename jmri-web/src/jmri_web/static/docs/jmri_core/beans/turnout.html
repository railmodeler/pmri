59    async def set_commanded_state(self, state: TurnoutState) -> None:
60        """Ask the layout to throw or close the switch.
61
62        The base implementation only updates the in-memory commanded state
63        and emits the signal. Driver subclasses override this to push a
64        hardware message *and then* call :meth:`super().set_commanded_state`.
65        """
66        prev = self._commanded_state
67        if prev == state:
68            return
69        self._commanded_state = state
70        await self.state_changed.emit(TurnoutStateChange("commanded", prev, state))
71        # For DIRECT feedback, known state mirrors commanded immediately.
72        if self.feedback_mode == TurnoutFeedback.DIRECT:
73            await self._set_known_state(state)
74
75    async def _set_known_state(self, state: TurnoutState) -> None:
76        """Driver hook: layout reported this state."""
77        prev = self._known_state
78        if prev == state:
79            return
80        self._known_state = state
81        await self.state_changed.emit(TurnoutStateChange("known", prev, state))

Layout turnout (point switch).

A turnout has two state values:

  • commanded_state — what we last asked the layout to do.
  • known_state — what the layout reports back.

Drivers update known_state when their feedback channel reports a change; this may differ from commanded_state until the move completes or if motorised feedback says the switch ended up in an INCONSISTENT pos.

Per-type bean registry. Subclass and override _create().

Attributes set on the class describe the bean type:

  • type_letter — single uppercase letter the bean class owns (e.g. "T" for Turnout). Must be set by subclass.
  • system_prefix — connection prefix (e.g. "L"). Set per-instance because one bean class can have many connection-specific managers.
