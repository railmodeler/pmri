jmri_server

jmri-server — Stage 3 of the JMRI Python rewrite.

A FastAPI + WebSocket server speaking JMRI's JSON wire protocol on top of jmri_core's in-memory InternalConnection. The HTTP and WebSocket endpoints share one dispatcher; every reply validates against the JSON schemas extracted from JMRI's jar in Stage 0.

Default ASGI entry point. uvicorn jmri_server:create_app --factory.

Bootstraps a multi-profile installation:

  • Reads <settings>/profiles.xml (if present) and exposes the registry on ctx.profile_registry. Users editing JMRI's profiles.xml can use this server against their existing setup.
  • Resolves the active profile (.active_profile marker → first profile → fallback default) and attaches a ConfigStore so user-created beans persist into the chosen profile's PanelPro.xml.

Tests that build the app via build_app() directly skip this setup for hermeticity.

Logging is configured inside the lifespan (see build_app()) rather than here — uvicorn's own dictConfig call happens between create_app returning and the lifespan startup, and it would wipe any handlers we installed pre-lifespan. Configuring in lifespan is the only spot that survives that reset.
